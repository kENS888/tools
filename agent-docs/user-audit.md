## ツールの利用者目線監査(2026-11-06 Kens決定)
本物の利用者の声がまだ無いので、利用者を演じる別のAIに、ツールを実際に操作させて点検する。

### いつ行うか
- ツールを変えた時・新しいツールを作った時は、mainに反映する前に毎回(変えた・作ったツールだけ)
- 初回の全体点検:需要調査(改善マニュアル7章2)で決めた注力3本から始め、残りは順に

### 監査役(1人＝別のAI 1本。作った経緯・Claudeの意図・結論は渡さない)
- 毎回入れる3人(全ツール共通)
  1. 検索から来た初めての人:スマホ、急いでいる、説明は読まない。Search Console の実際の検索語を入口として渡し、その答えが10秒で見つかるかを見る
  2. 毎月使う実務担当:PC、速さと正確さ重視。2回目以降の手間(履歴・入力候補・引き継ぎ)を見る
  3. 詳しくなくて不安な人:用語が分からない若手、または久しぶりに書類を作る人。用語、結果を信じられるか、出典の見せ方を見る
- ツールごとの4人目(立場の違う人・特別な場合):日割り＝家賃を受け取る大家/請求書・見積書・納品書・領収書＝書類を受け取る側の経理/発注書＝下請けに頼む小さな会社(取適法・支払期日)/源泉徴収＝報酬を払う会社の担当/営業日＝支払日を決める側/送付状＝初めて郵送する新入社員/消費税＝8%と10%が混ざる個人のお店の店主/経費精算＝承認する上司/年末調整＝配偶者・子どもを扶養している人/ふるさと納税＝住宅ローン控除・医療費控除がある人/残業代＝自分の残業代が正しいか疑っている会社員
- 正確さの監査役(別に1本):計算の正しさだけを見る(境界の日付・端数・祝日・改正点など)。税理士・経理の専門家の役はここで担い、利用者役には入れない
- UI・UXの監査役(別に1本、2026-11-07 Kens決定):利用者役の感想では原因まで分からない所を、画面のどこが悪いかで指摘する役。サイト全体のそろい方も見る
  - 入れる時:画面が変わる時は必ず(入力欄・ボタン・結果の出し方・並び・色・折りたたみ。1か所の小さな修正でも入れる)。新しいツール・初回の全体点検も。変更の大きさではなく「画面が変わるか」で決める
  - 入れない時:文章だけの変更(解説・よくある質問・出典・計算例の数字)、画面が変わらない計算の中身だけの変更
  - 渡すもの:プレビューのURL、agent-docs/design.md の「デザインの約束」「分かりやすさの約束」と agent-docs/past-findings.md の「過去の指摘」(これに反する案は出させない)。作った経緯・意図は渡さない
  - 見ること(PC 1366px・スマホ 390px の実際の画面、スクリーンショットを根拠に):最初に見える範囲で何をすればよいかと答えの場所が分かるか/答えが一番目立っているか/入力のしやすさ(数字のキーボード・単位・「300万」のような書き方・エラーの出し方)/空欄・入力の途中・ありえない値・結果が出た時の見え方/ほかのツールとのそろい方(ボタンの位置・折りたたみ・結果の形)/押せる大きさ44px以上・色の差・キーボードだけで操作できるか・ダークモード
  - 出し方:重要な順に最大5つ。「画面のどこで → 何が問題か → どう直すか」
  - 扱い:利用者役と重なる指摘は優先して直す。UI・UXの監査役だけの指摘は、小さく直せるものは直し、画面の形を変えるものは相談に回す。「過去の指摘」とぶつかる案は相談
  - モデル:Opus、思考量 medium
- 人数:文章だけの変更(解説・よくある質問・出典・計算例の数字)で画面が変わらない時は、正確さの監査役1本だけにする(2026-11-12 Kens承認。費用を抑えるため)。それ以外の小さな変更(画面の文言・1か所の修正)は共通の3人＋正確さ1本(画面が変わるならUI・UX 1本も)。大きな変更・初回の全体点検は4人＋正確さ1本＋UI・UX 1本
- 入れない役:日本語が母語でない人(このサイトの読者ではない)。目の不自由な人・高齢者は演技でなく、毎回の画面確認で文字の大きさ・色の差・読み上げを自動で点検する
- 選んだ理由:5つの軸(知識/端末/回数/気持ち/立場)で、つまずく所が違う人をそろえた。需要調査の結果や実際の検索語で見直す

### やり方
- 公開版かプレビューで、PC(1366px)とスマホ(390px)の両方で実際に操作させる。HTMLを読むだけにしない
- 演技の決まり:「10秒で分からなければ戻る」「説明文は読まない」など時間と行動を決める。点数が甘くならないよう、必ず不満を3つ挙げさせる
- 1人ずつ答えさせる:開いて10秒で何を入れればよいか分かったか/答えにたどり着けたか・迷った所/結果を信じられたか/また使うか・人に勧めるか/1〜10点(7点未満は直し案)

### 結果の扱い
- 採る:迷う・間違えるが減る/結果を信じやすくなる/また使いたくなる・勧めたくなる/見た目が分かりやすくなる。「迷う・間違える」以外の改善でも、良くなるものは採る(Kens)
- 相談する:「過去の指摘」とぶつかる案。両方の理由を並べてKensが決める
- 採らない:1人だけの好みで、ほかの人の点数を下げる案(理由を書いて報告)
- 2人以上が同じ指摘をしたら優先。1人だけの意見は相談に回す
- Kensへの報告:直す案/監査とClaudeで意見が分かれた点/直さない案とその理由
- 本物の利用者が来始めたら、AIの演技より実際の数字(どこで離れたか)を優先する
