## AI検索対策(AIに紹介されやすくする)
- 各ツールに「〇〇でできること」の要約ブロックを静的HTMLで置く(答えを先に1〜2文＋機能の箇条書き＋最終更新日)。AIのクローラーはJavaScriptを実行しないことが多いため、大事な説明はJSで描画しない
- 構造化データ：WebApplication(機能一覧・説明・更新日・運営者)、BreadcrumbList、FAQPage。トップはOrganization・WebSite・ItemList。解説記事は Article＋BreadcrumbList。本文と内容を一致させる
- /llms.txt にサイト概要とツール一覧、解説記事、「こんな質問に向いています」を記載。ツール・記事の追加時に更新
- robots.txt でAI検索用・学習用クローラーを明示的に許可
- よくある質問は「質問→1文目で答え→補足」の形。数値は具体的に、出典(国税庁)を書く
- ツールを更新したら最終更新日とsitemapのlastmodを更新

## 新しいツールを作る時の約束
- 計算ロジックは `<script id="core">` に分離し、Nodeでテストしてから公開(複数ページで共有する場合は /assets/ の外部ファイル)
- 画面の確認は Playwright(クラウドの作業環境では require('/opt/npm-tools/node_modules/playwright')、KensのPCの Claude Code では %APPDATA%\npm\node_modules\playwright。chromium.launch() そのまま)。npm で別バージョンを入れない。パソコン(1366×768)とスマホ(390px)の両方で確認。ローカルのサーバーは他の作業と同じポートを使っていないか確かめる(別のフォルダを配信していて誤判定したことがある)
- 広告枠は2か所(結果の下、ページ下部)。ボタンの近くには置かない
- フッターにトップ、解説記事、このサイトについて、プライバシーポリシー、お問い合わせへのリンクを付ける(2026-11-04 から5つ)
- そのページだけの解説・具体的な計算例・公的な出典リンク(確認日つき)を、開いた状態の section.gx で置く(2026-11-04)。他のページと同じ文章を使い回さない
- トップページ(/index.html)の一覧・「どのツールを使えばいい？」の表、sitemap.xml、llms.txt に追加する。canonicalは https://shigoto-keisan.com/〜
- OGPのタグとファビコンの3行を head に入れ、/assets/og/<フォルダ名>.png のカード画像を作る(既存の画像と同じデザイン。Playwrightで描画)
- コピーは navigator.clipboard ＋ execCommand の予備方式。navigator.share は使わない(Braveで不具合)
- 画面テストで、開閉・色の変化・表示の切り替えを確かめる時は、切り替わりを待ってから見る(waitFor か、短い間隔で読み直す)。すぐに読むと、製品は正しいのにテストが落ちる(2026-11-10、/kabu-shinkoku/ で2回)
- 入力フォームを質問の流れ(診断型)に作り直す時は、元の判定の条件を一覧にし、すべての道筋でそれぞれの条件を聞いているかをテストで確かめる(2026-11-10、副業の所得を一部の道筋で聞いていなかった)
